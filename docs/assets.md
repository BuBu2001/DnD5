# Справочник графики и ассетов (DOC-03: реестр ресурсов)

Документ описывает, **где находится графика, откуда она берётся и как
пересоздаётся**. Все изображения в репозитории сгенерированы процедурно —
внешних заимствованных ассетов нет, лицензионных ограничений нет.

## 1. Где лежит графика

```
assets/textures/
  tokens/      fighter.png, rogue.png, goblin.png        — токены боя 32×32 RGBA
  tiles/       floor_stone.png, wall_stone.png, rubble.png — плитки карты 32×32
  icons/       advantage.png, disadvantage.png, prone.png  — иконки состояний 24×24
  portraits/   fighter.png, rogue.png, goblin.png        — портреты для UI 64×64
  tokens.manifest.json — перечень кадров атласа (вход упаковщика)
  tokens.atlas.json    — раскладка атласа (выход упаковщика, схема atlas.schema.json)
  preview_sheet.png    — лист-превью всех кадров (для быстрой проверки глазами)
```

## 2. Откуда берётся (генератор)

Единственный источник — **`scripts/gen_assets.py`** (Python 3, только stdlib:
zlib/struct, без Pillow). Изображения строятся по символьным картам и
примитивам, детерминированно: сид **20251102**, повторный запуск даёт
байт-в-байт те же PNG.

```bash
python3 scripts/gen_assets.py --root assets --preview
```

Стиль — пиксель-арт «сверху-вниз»: токены читаются на клетке 32×32
(файтер: стальной шлем с красным плюмажем и меч; рог: фиолетовый плащ с
капюшоном и кинжал; гоблин: зелёная кожа, красные глаза, длинные уши),
плитки — каменная кладка с шумом, иконки — стрелки преимущества/помехи и
«лёжа» для состояния prone.

## 3. Как попадает в игру

1. `scripts/gen_assets.py` → исходные PNG в `assets/textures/**`;
2. `tools/asset_packer --manifest assets/textures/tokens.manifest.json
   --output assets/textures/tokens.atlas.json --padding 2` → раскладка атласа
   (12 кадров, страница 256×256, использование площади ~31 %);
3. движок декодирует PNG в RGBA через `engine/resource/texture_loader`
   (stb_image, см. п. 4) и загружает в текстуры OpenGL (`GlRenderer::
   create_texture_rgba`);
4. проверка корректности — интеграционный тест `texture_loader_png`
   (декодирование, прозрачность углов, отказ на битых данных).

## 4. Сторонние компоненты графики

| Компонент | Расположение | Лицензия | Назначение |
|-----------|--------------|----------|------------|
| stb_image v2.30 | `third_party/stb/stb_image.h` | Public Domain (nothings/stb, таблица 4.16 ТЗ) | декодирование PNG в RGBA |

Сборка stb_image ограничена флагами `STBI_ONLY_PNG` (только PNG) и
выключением предупреждений GCC для стороннего кода (наш `-Werror` на него
не распространяется).

## 5. Замена на «настоящую» графику

Форматы и пути зафиксированы манифестом: чтобы заменить процедурный
пиксель-арт на рисованные ассеты, достаточно положить PNG того же имени и
размера в соответствующий каталог (или поправить `source` в манифесте) и
перезапустить упаковщик. Код движка и схемы данных менять не требуется
(DATA-E05: все пути виртуальные `assets:/…`).

Где взять готовую графику при необходимости (CC0-источники, проверяйте
лицензию каждого файла):
- Kenney.nl — пакеты tiny dungeon / RPG (CC0);
- OpenGameArt.org — раздел 2D top-down (фильтр CC0);
- itch.io — бесплатные паки в разделе game assets.

## 6. Звук

`assets/audio/` на V0.4 пуст; подсистема SDL2_mixer готова (FR-E50…E52),
ошибки загрузки пишутся в журнал и не прерывают игру. Генерация базовых
эффектов (клик, попадание, промах) запланирована отдельно.
